# 指标、结算与渠道价值规则

## 一、分析对象与用户级关联

每条模拟记录代表一位可被内部识别为抖音来源的用户，保留团购券订单、内部线索、商机、门店承接、到店 / 试驾与锁单事件，以及服务商、来源、内容资产、直播间和门店等归属字段。平台侧曝光、观看人数和点击数据不在本 Demo 的可用数据范围内。

```text
抖音可识别转化入口
├─ 团购券购买
└─ 留资
       ↓
关联内部线索 / 商机
       ↓
毛线索 → 净线索 → 创建商机 → 开启商机 → 门店下发承接 → 预约到店 → 到店 / 试驾 → 锁单
```

看板按**可识别抖音入口发生日期**筛选用户群。订单和留资是可被内部关联的外部转化行为；线索与商机是内部销售状态。它们可同时出现在同一用户旅程中，但不是三条互斥漏斗，也不将团购券购买强制当作线索或锁单的必经前置条件。

## 二、团购券订单与履约

| 状态 | 定义 | 关注问题 |
| --- | --- | --- |
| 未使用 | 已支付但尚未核销 | 如何推动用户预约、到店或使用权益 |
| 已核销 | 已完成团购券履约 | 门店接待与后续销售承接是否顺畅 |
| 已退款 | 支付后退出券链路 | 权益承诺、价格预期或履约说明是否存在偏差 |

订单履约单独呈现。它和销售漏斗通过用户关联共同观察，但“订单数大”不等价于“最终成交能力强”。

## 三、经营与销售漏斗指标

```text
净线索率 = 净线索数 / 毛线索数
线索→创建率 = 创建商机数 / 毛线索数
创开率 = 开启商机数 / 创建商机数
门店承接率 = 门店已承接数 / 开启商机数
预约到店率 = 预约到店数 / 门店已承接数
到店/试驾率 = 到店/试驾数 / 预约到店数
试驾→锁单率 = 锁单数 / 到店/试驾数
```

“最大漏斗流失”按各销售环节的流失人数排序，同时呈现环节转化率。Demo 的主要观察点是**创建商机 → 开启商机**：当该环节下降时，优先排查门店分单、排班、跟进覆盖和待开启商机，而不是直接扩大投放。

## 四、时效与成熟商机

用户级事件支持计算：

- 线索→创建
- 创建→开启
- 开启→门店下发
- 门店下发→预约
- 预约→到店 / 试驾
- 创建→锁单

近期创建商机尚未到达正常锁单周期，若直接与早期批次比较会使锁单率虚低。因此以下指标默认限制为创建时间已进入 14 天观察窗口的**成熟商机群**：

- 成熟商机锁单率
- 成熟商机 7 日锁单率
- 创建→锁单中位周期

创开率和门店承接率仍可观察近期商机，用于快速识别承接卡点。

## 五、服务商、来源与直播间

每位模拟用户绑定一个 `settlement_provider`，与服务商归属一致。最终锁单计入对应服务商的结算锁单，用于服务商复盘与后续资源调整。

服务商、来源和直播间是不同维度：

| 维度 | 主要用途 |
| --- | --- |
| 服务商 | 结算、投放资源和整体经营评估 |
| 来源 | 比较直播间与私信的规模、承接和锁单效率 |
| 内容资产 / 直播间 | 评估具体内容场、直播场的锁单效果与优化优先级 |

公开 Demo 目前只模拟了“直播间”和“私信”两个可稳定识别来源。若业务数据可稳定标识短视频团购、直播间私信等入口，可按相同字段体系扩展，但不应凭空拆分来源口径。

## 六、渠道价值分析

渠道价值分析仅针对最终锁单且已关联抖音触达的用户。它不采用首次触达或末次触达归因，而是按用户在抖音触达**之前**的 CRM 状态进行互斥分层：

| 触达前 CRM 状态 | 价值类型 | 业务解释 |
| --- | --- | --- |
| 无有效历史记录 | 新增贡献 | 带来此前没有有效内部销售记录的用户 |
| 历史战败或长期未成交 | 战败激活 | 帮助曾经停滞的用户重新进入销售推进 |
| 已有进行中商机或销售跟进 | 存量促转 | 对正在考虑的用户形成内容、权益或决策促进 |

该页面的表述是“关联贡献 / 价值分层”，不能据此直接声称严格因果增量。

## 七、周度归因 Skill 与经营诊断

公开看板不直接展示异常归因页面；它负责按日常经营需求查看漏斗、时效、直播间、车型和服务商差异。需要解释周度 KPI 波动时，使用仓库内的 `weekly-ops-attribution` Skill 读取确定性计算结果，按“**指标拆解树 → 多维贡献拆分 → 明细下钻 → 待业务确认**”执行。Skill 比较最近两个完整自然周；若没有足够完整周期，则应停止并提示数据不足，而不是由页面自动编造结论。

归因页的前提是：目前无法取得抖音平台的曝光、观看或点击分母。因此，**入口指标不能使用“曝光 × 转化率”拆解**；只对内部销售漏斗使用业务链路中的乘法关系。

```text
商品订单数 = 直播间订单 + 私信订单
毛线索数 = 直播间毛线索 + 私信毛线索
退款订单数 = 直播间退款订单 + 私信退款订单
```

订单、毛线索和退款的变化可继续按服务商、内容资产或直播间做加法贡献拆分，定位哪一个可识别归属带来了变动；这只能解释**已进入内部可观测范围的入口数量**，不能推断平台曝光或观看变化。

内部销售指标使用乘法关系。例如：

```text
创建商机数 = 毛线索数 × 线索→商机创建率
开启商机数 = 毛线索数 × 线索→商机创建率 × 商机开启率
门店承接数 = 开启商机数 × 门店承接率
锁单数 = 毛线索数 × 线索→商机创建率 × 商机开启率 × 门店承接率 × 预约到店率 × 到店/试驾率 × 试驾→锁单率
```

离线归因结果对内部销售指标的每个因子计算其对目标变动的对称贡献，识别变化主要来自线索规模，还是创建、开启、门店承接等环节效率。随后将目标指标变化按维度拆分，并保留对应的用户级明细，供业务人员核验，而不是将归因结果直接当作确定根因。

下钻维度按“服务商 → 来源 / 内容资产 / 直播间 → 区域 → 门店 → 产品系列”组织。诊断时需结合异常分布判断：

- 订单、毛线索或退款变化：先按来源、直播间、服务商或内容资产拆分，判断哪个已识别入口或归属发生变化；不将其表述为曝光或观看转化率问题；
- 开启商机变化：先看毛线索、线索→商机创建率、商机开启率三个因子，再按服务商、门店、直播间拆分；
- 多来源集中在同一门店或区域的创开 / 承接异常：优先判断门店承接问题；
- 创开稳定、到店 / 试驾或锁单下降：再看预约、到店体验和成交推进；
- 最后在当前周期、选定维度下查看未进入目标环节的合成用户明细；锁单率与周期仍只使用成熟商机，避免观察窗口差异带来的误判。

归因结果只用于提出优先核验的问题，不直接下发任务、归属责任人或自动生成运营策略。

## 八、公开发布边界

1. 所有记录必须带有合成数据标记；
2. 用户、订单、线索、商机和锁单编号均为合成编号且唯一；
3. 当前销售阶段时间不得倒序，且不得晚于观察截止时间；
4. 渠道价值标签必须与抖音触达前 CRM 状态一致；
5. 服务商结算归属必须与用户记录一致；
6. 不输出真实业务数据、内部渠道编码、生产系统地址或凭据。
