# 周度经营归因

将归因分析标准化为“发现问题—定位问题—下发任务—制定策略—执行策略—效果分析”的闭环。让确定性数据查询和规则计算提供事实，让 Agent 负责编排步骤、解释结果和生成任务草稿。

## 使用前提

1. 读取 [references/dqs-schema.md](references/dqs-schema.md)，确认 DQS 表名、字段映射和查询粒度已配置。
2. 读取 [references/metric-tree.md](references/metric-tree.md)，选择目标指标对应的拆解树。
3. 读取 [references/attribution-rules.md](references/attribution-rules.md)，应用异常、多维贡献和明细下钻规则。
4. 需要生成运营任务时读取 [references/action-playbook.md](references/action-playbook.md)。
5. 需要输出报告或看板 JSON 时分别读取 [references/report-template.md](references/report-template.md) 和 [references/output-schema.md](references/output-schema.md)。
6. 用定时 Agent 执行时读取 [references/scheduled-task-prompt.md](references/scheduled-task-prompt.md)。

若 DQS 表名或必需字段仍为占位符，停止正式归因；列出缺失配置，不得猜测表名、字段或数据。

## 固定工作流

### 1. 确定分析周期

- 使用 `Asia/Shanghai` 时区。
- 默认比较最近两个已经结束的完整自然周，周一至周日。
- 不使用“运行日向前七天”替代自然周。
- 对 30 日内锁单率等成熟指标，仅纳入已完成观察窗口的创建销售机会用户。
- 若指定了其他两个周期，使用等长周期并明确起止日期。

### 2. 校验数据质量

在任何业务分析前检查：

- 当前周和基准周是否均有数据；
- 用户、订单、线索、销售机会编码是否存在异常重复；
- 关键事件时间是否按业务顺序排列；
- 来源、服务商、直播间、区域和门店的未映射率；
- 指标分子是否大于分母；
- 30 日锁单指标是否满足成熟观察期；
- 当前周数据量是否出现疑似数据断流。

数据质量未通过时，只输出数据问题和修复建议，不输出经营归因。

### 3. 发现异常指标

按指标配置计算当前周、基准周、绝对变化、相对变化和样本量。只有同时满足最小样本量和异常阈值时，才生成正式异常。

按业务优先级检查：

1. 锁单数、30 日内锁单率；
2. 创开率、创建至开启时长；
3. 到店/试驾率及后续锁单率；
4. 团购券订单、退款率、核销率；
5. 毛线索、净线索及创建销售机会效率。

### 4. 执行拆解树

- 对订单、退款、线索等加法指标，按来源或业务维度计算分项变化贡献。
- 对开启销售机会数、锁单数等乘法指标，按指标树计算各因子的对称贡献。
- 确保各因子贡献之和能够回到目标指标总变化，允许存在四舍五入误差。
- 输出主要正向因子、主要负向因子及其贡献占比。
- 不根据平台曝光、观看或点击推断入口变化，除非 DQS 明确提供这些数据。

### 5. 执行多维分析

选取拆解树中影响最大的可行动因子，按配置顺序分析服务商、来源、直播间、区域、门店和车型。

- 对数量指标，计算维值的实际增减量。
- 对比率指标，计算 `当前分母 ×（当前比率 - 基准比率）` 对应的业务影响量。
- 同时展示当前值、基准值、分母、变化量和影响量。
- 按影响量绝对值排序，不得只按转化率高低排序。
- 设置最小样本量，避免小样本维值占据首位。

### 6. 执行明细下钻

根据异常节点生成可执行的明细条件：

- 创开率下降：已创建未开启、或创建至开启超过 SLA 的销售机会；
- 到店率下降：已开启未预约、已预约未到店用户；
- 锁单率下降：已到店/试驾但成熟期内未锁单用户；
- 退款率上升：退款订单及对应商品、直播间、服务商和退款时长；
- 创建率下降：已留资但未创建销售机会的用户。

仅输出完成任务所需字段。公开或演示场景必须使用合成或脱敏标识，不输出真实个人信息。

### 7. 生成任务草稿

读取动作手册，将“指标 + 主要因子 + 影响维度”映射为：

- 问题描述；
- 数据证据；
- 影响规模；
- 建议动作；
- 责任角色；
- 建议完成时间；
- 后续验证指标。

Agent 只能生成任务草稿。正式任务下发、预算调整和服务商结算必须由业务负责人确认。

### 8. 评估策略效果

若策略登记表中存在与异常范围相关的 SOP、投流或商品策略：

- 检查策略上线时间、执行范围、试点组、对照组和目标指标；
- 优先计算试点组与对照组的同期差异变化；
- 无对照组时，只表述为“策略上线后观察到”，不得写成确定因果；
- 对锁单率使用完整成熟用户组，对创开率和承接时效可使用近期用户；
- 检查策略是否改善目标指标，以及是否带来退款率等副作用。

### 9. 生成输出

同时生成：

1. 结构化归因结果，供自动化看板读取；
2. 面向运营和业务的周度归因报告；
3. 待确认的任务草稿；
4. 数据质量问题和待验证假设。

所有结论必须包含数据证据、比较周期和影响维度。区分“数据事实”“主要影响因素”和“待验证原因”。

## Agent 行为约束

- 不自行修改指标定义、异常阈值、来源映射和结算归属。
- 不把相关关系写成确定因果。
- 不把团购券支付等同于最终成交。
- 不将不同创建周期的分子和分母直接相除。
- 不因没有异常而强行生成业务问题。
- 不在数据质量失败时给出运营结论。
- 不在未经批准的情况下发送任务、修改预算或调整投流。

## 成功标准

- 两个分析周期边界正确且等长；
- 异常满足样本量和阈值要求；
- 拆解贡献可回算到核心指标变化；
- 多维分析能够定位主要业务维值；
- 明细条件与异常节点一致；
- 任务建议有责任角色和验证指标；
- 策略效果结论标明因果强度；
- 报告与看板 JSON 使用同一份事实结果。
